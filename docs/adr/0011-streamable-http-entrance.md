# Streamable HTTP entrance alongside stdio

This server gains a second entrance, `build/http.js`, for hosts that cannot spawn a local process. `POST /mcp` is stateless: the SDK v2 `createMcpHandler` builds a fresh server from the same tool definitions per request, issues no session id, and `GET`/`DELETE` on `/mcp` answer `405`. We do not adopt SSE as a persistent transport or session store; a response streams as `text/event-stream` only when the client's `Accept` header asks for it, otherwise plain JSON. `X-API-Key` is checked first, with `?api_key` as a query fallback for hosts that cannot set custom headers, using a length-checked constant-time comparison. The 11 OAuth/OpenID discovery GET paths and `POST /register` answer empty `{}` `200` before any auth check, because claude.ai probes them pre-authentication and a `404` there breaks the connector and can trigger a 429 retry storm; we do not implement a real OAuth issuer, since this server gates with a static API key instead of an OAuth flow. Auth failures split by cause, matching the mcp-servers shared `checkApiKey` pattern in asana-mcp `src/run_with_auth.ts`: a missing or empty key answers `401` (nothing was presented), a present-but-wrong key answers `403` (an identity was presented and rejected). We rejected collapsing both cases into a single `401`, since the split is now the shared convention across mcp-servers HTTP entrances and lets a caller tell "no credential sent" apart from "credential sent is wrong" without probing further.
